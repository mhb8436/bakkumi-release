The problem

Files that travel between macOS and Windows lose their names in two different ways. A file from Windows can arrive with its name read in the wrong encoding. And a name written on a Mac is stored with its Korean letters taken apart, which looks fine on the Mac and scattered on Windows. You cannot see the second one on a Mac at all.

What it does

  • Repairs broken names. bakkumi guesses the original encoding (CP949, Shift_JIS, GB18030, Big5 and more), checks that the repair round-trips, and only touches names it can prove. If it is not certain, it leaves the file alone. You can switch the encoding with a live preview.
  • Tidies decomposed Hangul. Every rename normalizes the name so it stays in one piece on Windows. The Show as Windows Sees It switch shows what the other side would get, before you change anything.
  • The common jobs, in seconds. Replace the whole name, find and replace, prefix and suffix, numbering by name, date, size or the time a photo was taken, change the extension, tidy spaces, make names safe for Windows. Fill in the fields you need. There are no rules to stack and no order to arrange.
  • Nothing happens without a preview. The preview cannot be turned off. If even one new name would collide, the rename button stays locked. bakkumi never uses the system path that overwrites a file silently. Undo works batch by batch.
  • Finder integration: right-click to rename here, plus the Services menu and Open With.

Install

  1. Open the downloaded bakkumi.dmg and drag bakkumi into Applications. Or, with Homebrew: brew install --cask mhb8436/bakkumi/bakkumi.
  2. Launch it. The app is signed and notarized by Apple, so it opens without any workaround.
  3. Optional: turn on the Finder extension for the right-click menu. See the first question below.

Questions

The right-click menu in Finder does not show bakkumi

macOS turns off Finder extensions by default. Open System Settings › General › Login Items & Extensions › Finder Extensions and switch on bakkumi.

Why does bakkumi ask for permission to a folder?

A Finder extension can tell bakkumi which folder you picked, but macOS does not let it hand over permission to change anything inside. Allowing a folder once lets bakkumi rename inside it without asking again. The folders you allowed are listed in the sidebar. Right-click one and choose Remove from List to take the permission back.

The preview shows the same name on both sides

Then the name looks fine but its Korean letters are stored taken apart. Windows shows it that way. The status column says Tidy up, and turning on Show as Windows Sees It shows the difference.

Some names are marked "Cannot repair"

Those names were already damaged before they reached you: the wrong encoding replaced some letters with a placeholder character, and the original is gone. bakkumi says so instead of guessing, and skips them.

Names on my USB stick still come apart

macOS writes every name on an exFAT or FAT32 volume in the decomposed form, whatever an app does. bakkumi tells you when a volume cannot store joined names instead of pretending it worked. Repairing broken names still works there.

How do I get updates?

Choose bakkumi › Check for Updates. bakkumi never checks on its own. If you installed with Homebrew, brew upgrade --cask bakkumi.

Privacy

bakkumi collects nothing.

  • No personal data is collected, stored or transmitted.
  • No analytics, no tracking, no advertising identifiers.
  • Your files, and their names, never leave your Mac. Opening a folder sends nothing anywhere.
  • There are exactly two moments when bakkumi uses the network, and both happen only when you ask for them:
    • If you put the {place} tag in a name, the GPS coordinates already stored in the photo, rounded to three decimals, are sent to Apple's geocoding service to get a place name. Nothing is kept after you quit.
    • If you choose Check for Updates, bakkumi reads the latest version number from GitHub. Nothing about you or your files is sent.

어떤 문제인가

맥과 윈도우 사이를 오가는 파일은 이름이 두 가지 방식으로 망가집니다. 윈도우에서 온 파일은 이름이 잘못된 인코딩으로 읽혀 도착하고, 맥에서 지은 이름은 한글이 자모 단위로 쪼개져 저장됩니다. 후자는 맥에서는 멀쩡해 보이고 윈도우에서는 흩어져 보이는데, 맥에서는 눈으로 구분할 수가 없습니다.

맥에서 지은 이름, 윈도우에서 보면 ㅎㅏㄴㄱㅡㄹ ㅁㅔㅁㅗ.txt
바꾸미를 거친 뒤, 윈도우에서 보면 한글 메모.txt

이 앱이 하는 일

  • 깨진 이름을 되살립니다. 원래 인코딩(CP949, Shift_JIS, GB18030, Big5 등)을 추정하고, 되돌린 이름이 왕복 검증을 통과하는지 확인한 뒤 확인된 것만 고칩니다. 확실하지 않으면 손대지 않습니다. 인코딩을 바꾸면 미리보기가 바로 따라옵니다.
  • 자모 분리를 정리합니다. 이름을 바꿀 때마다 윈도우에서도 한 글자로 남게 정규화합니다. 윈도우에서 보이는 대로를 켜면 바꾸기 전에 받는 쪽이 볼 모습을 미리 봅니다.
  • 흔한 일은 몇 초면 끝납니다. 이름 전체 교체, 찾아 바꾸기, 앞뒤 덧붙이기, 번호 매기기(이름순·날짜순·크기순·촬영순), 확장자 변경, 공백 정리, 윈도우에서 쓸 수 있는 이름으로 다듬기. 빈칸을 채우면 끝입니다. 규칙을 쌓거나 순서를 정할 필요가 없습니다.
  • 미리보기 없이는 아무것도 일어나지 않습니다. 미리보기는 끌 수 없습니다. 겹치는 이름이 하나라도 있으면 실행 버튼이 잠깁니다. 같은 이름을 말없이 덮어쓰는 시스템 경로는 쓰지 않습니다. 되돌리기는 묶음 단위로 됩니다.
  • Finder 연동: 우클릭으로 여기서 이름 바꾸기, 서비스 메뉴, 다음으로 열기.

자주 묻는 것

Finder 우클릭 메뉴에 bakkumi가 안 보입니다

macOS는 Finder 확장을 기본으로 꺼 둡니다. 시스템 설정 › 일반 › 로그인 항목 및 확장 프로그램 › Finder 확장 프로그램에서 bakkumi를 켜주세요.

왜 폴더 접근 권한을 묻나요?

Finder 확장은 어떤 폴더를 골랐는지 알려줄 수 있지만, macOS가 그 안을 고칠 권한까지 넘기는 것은 허용하지 않습니다. 폴더를 한 번 허용하면 그 안에서는 다시 묻지 않습니다. 허용한 폴더는 왼쪽 목록에 보이고, 우클릭해서 목록에서 빼기를 누르면 권한이 사라집니다.

미리보기의 두 이름이 똑같아 보입니다

이름은 멀쩡해 보이지만 한글이 자모 단위로 쪼개져 저장돼 있는 경우입니다. 윈도우는 그 상태를 그대로 보여 줍니다. 상태 칸에 정리라고 적히고, 윈도우에서 보이는 대로를 켜면 차이가 보입니다.

어떤 이름은 "복구 불가"라고 나옵니다

파일이 도착하기 전에 이미 망가진 이름입니다. 잘못된 인코딩이 일부 글자를 대체 문자로 바꿔 버려 원래 글자가 남아 있지 않습니다. 바꾸미는 짐작으로 채우지 않고 그 사실을 말한 뒤 건너뜁니다.

USB 메모리에서는 여전히 자모가 흩어집니다

macOS는 exFAT·FAT32 볼륨에는 어떤 앱이 무엇을 하든 모든 이름을 분리된 형태로 씁니다. 바꾸미는 그 볼륨에서 합쳐 저장할 수 없다는 사실을 알려 줄 뿐, 된 것처럼 꾸미지 않습니다. 깨진 이름 복구는 그 볼륨에서도 됩니다.

업데이트는 어떻게 받나요?

bakkumi › 업데이트 확인을 누릅니다. 바꾸미가 스스로 확인하는 일은 없습니다. Homebrew로 설치했다면 brew upgrade --cask bakkumi.
